# Per-method research audit

This file is the method-by-method research record for the isolated module. The
compatibility column means the mathematical input is compatible with Java
26.1.2, 26.2, and 26.3; `oracle` means the final result still requires a
version-matched Minecraft world-generation adapter. A confidence below 85%
means the method is intentionally not marked complete.

## Sources and evidence boundary

The implementation audit used the standalone SeedcrackerX checkout, the
standalone addon world-generation probes, the cached 26.1.2 and 26.3 merged
Minecraft jars, the 26.2 embedded server jar and data extracts retained in this
directory, and the public references listed in `SEED_CRACKING_METHODS.md`.
`WorldgenRandom` and `RandomSupport` decompiled class output was byte-identical
between 26.1.2 and 26.3; the embedded 26.2 jar was used for the audited
placement, outpost, portal, and structure-start paths. Internal self-tests
prove algebraic consistency only. They do not replace generated-world vectors,
so rows requiring Minecraft runtime, external CV, or solver dependencies remain
below 85% and are intentionally incomplete.

The 26.1.2 and 26.3 `RandomSpreadStructurePlacement` implementations have a
package/class refactor: 26.1.2 places shared placement logic in
`AbstractSpreadingStructurePlacement`, while 26.3 moves it into
`StructurePlacement`. Codec ownership and signatures differ, so byte-for-byte
class comparison is not a valid compatibility test. Their audited region and
offset formulas agree, but codec/class ownership differs and generated-world
vectors are absent; full structure-start recovery therefore remains below the
completion threshold.
